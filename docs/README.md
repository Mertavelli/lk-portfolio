# /docs

This folder contains source material and strategic context for the development of louiskarakas.com.

The files are not all current and should not be copied blindly.

## Read First

Before changing the website, read:

1. `POSITIONING.md`
2. the current website code and content
3. all relevant supporting documents in this folder

`POSITIONING.md` is the current strategic ground truth.

If older material conflicts with `POSITIONING.md`, follow `POSITIONING.md`.

## Purpose of This Folder

The material in `/docs` can be used to:

- understand the current positioning
- extract useful ideas
- find research-backed concepts
- reuse strong visual patterns
- understand previous thinking
- create new HTML/CSS/components for the website

The goal is synthesis, not reproduction.

## Source Types

### Previous consulting / expertise decks

Use these as:

- visual references
- conceptual inspiration
- examples of pacing, diagrams, cards, statements, and editorial layouts

Do not:

- copy them 1:1
- preserve outdated messaging
- preserve unnecessary buzzwords
- preserve claims that are no longer useful
- force old categories into the new positioning

### Research papers

Use these as:

- credibility sources
- conceptual support
- evidence for technical principles

Do not:

- invent findings
- overstate small studies
- turn academic language into marketing claims without justification

### Positioning documents

Use these as the current source of truth for:

- audience

- tone
- website messaging
- commercial direction

## Current Website Goal

The website should communicate:

**AI Strategy & Engineering**

The visitor should quickly understand that Louis can:

1. understand how a business works
2. identify where AI can create real leverage
3. design the target workflow and system
4. build the production software himself

This combination of strategic thinking and technical implementation is the core differentiation.

## Primary Visitor

Assume an important visitor is:

A Managing Partner or owner of a strategy / management consulting boutique who received a short cold email and clicked the website to assess credibility.

Within roughly 10 seconds, the site should answer:

- Who is Louis?
- What does he actually do?
- Does he understand professional-services workflows?
- Can he build real systems?
- Is this more than generic AI consulting?

## Content Principles

### Keep

- strong personal identity

- technical depth
- founder history
- research
- distinctive visual language
- concise writing

### Avoid

- generic AI agency aesthetics
- excessive sales copy
- fake personalization
- long capability lists
- repeated buzzwords

## Visual Principles

Use the current website as the primary design system.

Prefer:

- black / off-white / existing green accent
- strong typography
- editorial layouts
- restrained diagrams
- clean grids
- subtle interaction
- real conceptual visuals

Avoid:

- glowing AI orbs
- neural-network graphics
- robots
- generic SaaS gradients
- stock illustrations
- decorative complexity without meaning

## Workflow for Codex

Before implementing a major new section:

1. Inspect the current website.
2. Read `POSITIONING.md`.
3. Review relevant files in `/docs`.
4. Extract only the strongest ideas.
5. Propose a coherent section structure.
6. Implement it using the existing design system.
7. Review it from the perspective of a Managing Partner.
8. Remove anything generic, repetitive, buzzword-heavy, or overly salesy.
9. Check mobile responsiveness.
10. Keep the personal website character intact.

## Final Test

Before considering a change complete, ask:

**Does this make Louis look more like a thoughtful AI Strategy & Engineering advisor who can also build, or does it make him look like another AI agency / freelancer?**

If the second is true, simplify.
